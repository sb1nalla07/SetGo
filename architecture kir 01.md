# Архитектура MVP — AI Assistant for Simracing Setups

## Выделение сервисов

В MVP — один HTTP-сервис: **Setup Recommendation Service** (FastAPI + SQLite). Frontend — клиент этого сервиса, не отдельный API-сервис (не имеет собственного публичного HTTP API, не описывается OpenAPI).

Если база правил или штат экспертов вырастут, «базу знаний» можно вынести в отдельный сервис с собственным API (CRUD над `parameters`/`rules`) — это не входит в MVP.

## Компоненты и границы

### Frontend
- Веб-форма: пилот вводит жалобу на поведение машины свободным текстом (единственное
  поле запроса, [api-contract.md](api-contract.md)).
- Состояния интерфейса: загрузка, рекомендация найдена, совпадений нет, ошибка запроса.
- Компонент рекомендации: отображает параметр, направление изменения, ожидаемый эффект
  и ограничения — всё, что пришло в ответе backend.
- Frontend не хранит данные и не содержит логику подбора рекомендаций — только
  валидация формы перед отправкой и отображение ответа backend.
- Общение с backend — исключительно через контракт `POST /api/v1/recommendations`
  и `GET /health` ([api-contract.md](api-contract.md)).

### Setup Recommendation Service (FastAPI)
- Единая точка входа для рекомендаций: `POST /api/v1/recommendations`.
- Валидирует входящий запрос по контракту (обязательные поля, допустимая длина текста).
- Сопоставляет жалобу с условиями экспертных правил, хранящихся в SQLite.
- Перед сравнением исключает из выборки правила, не прошедшие проверку  — непроверенное правило не может попасть в ответ ни при каких условиях.
- Возвращает один из трёх исходов: совпадение (одна или несколько рекомендаций),
  отсутствие совпадения, ошибка.
- Не генерирует рекомендации произвольно — в MVP только детерминированный поиск по базе правил.
- `GET /health` — проверка, что сервис запущен и отвечает.

### SQLite (доступ через SQLAlchemy ORM)
- Источник истины для параметров сетапа и экспертных правил, backend только читает из неё.
- Доступ из кода — через модели SQLAlchemy, а не сырые `sqlite3`-запросы: параметризация
  запросов из коробки, модели — единый источник схемы вместо ручного маппинга строк. Пример моделей — ветка `feature/sqlalchemy-data-layer`.
- `parameters`: id, каноническое имя, единица измерения, описание влияния на поведение машины, диапазон/ограничения.
- `rules`: id, симптом/условие, ссылка на `parameter_id`, направление изменения, эффект, ограничения, применимость, статус проверки, основание/источник.
- Наполняется командой данных.

## Поток данных

1. Пилот вводит жалобу в форме на frontend.
2. Frontend отправляет `POST /api/v1/recommendations` с телом запроса.
3. Backend валидирует запрос; при нарушении контракта — возвращает ошибку 400.
4. Backend ищет в SQLite правила, условие которых соответствует жалобе, среди правил со статусом «разрешено к выдаче».
5. Если совпадений нет — backend возвращает ответ `no_match`.
6. Если совпадения есть — backend формирует список рекомендаций (параметр, направление, эффект, ограничения) и возвращает ответ `match`.
7. Frontend показывает результат: компонент рекомендации, сообщение об отсутствии совпадения или сообщение об ошибке.
8. Пилот проверяет рекомендацию в симуляторе (вне границ MVP-сервиса).

## Ответственность компонентов

| Компонент | Отвечает за | Не отвечает за |
|---|---|---|
| Frontend | форму ввода, состояния UI, отображение рекомендации | подбор правил, хранение данных, бизнес-логику |
| Setup Recommendation Service (FastAPI) | валидацию запроса, поиск правил, формирование ответа, `/health` | генерацию произвольных советов, редактирование содержимого правил |
| SQLite | хранение параметров и правил, статус проверки каждого правила | сопоставление жалобы с правилом |

## Вне границ MVP

- Аутентификация и профили пользователей.
- Генерация рекомендаций через LLM — возможный предмет отдельного решения.
- Хранение истории запросов пилота сверх того, что нужно для формы обратной связи - обсуждается отдельно, не предполагается по умолчанию в MVP.
- Поддержка нескольких автомобилей/трасс одновременно — MVP ограничен одним автомобилем и овальными трассами.
